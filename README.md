# Archive — уязвимый файловый архив

Учебный таск в стиле HackTheBox: веб-архив документов с ролевым доступом (guest / engineer / admin). В приложение намеренно заложена уязвимость контроля доступа (broken access control / IDOR), позволяющая обычному пользователю прочитать содержимое секретных документов.

> ⚠️ Приложение специально сделано уязвимым. Запускайте только в изолированной среде (локально или в ВМ), не выставляйте в интернет.

## Архитектура

| Сервис     | Технологии                         | Порт |
|------------|------------------------------------|------|
| `frontend` | Next.js 15, React 19               | 3000 |
| `backend`  | FastAPI, SQLAlchemy, JWT (python-jose) | 8000 |
| `db`       | PostgreSQL 16                      | —    |

```
archive/
├── docker-compose.yml   оркестрация трёх сервисов
├── .env.example         шаблон переменных окружения
├── POC.py               эксплойт уязвимости в /search
├── fastapi/             бэкенд (main.py, models.py, database.py, initdb.py)
└── frontend/            фронтенд на Next.js
```

## Запуск в Docker

```bash
cp .env.example .env
```

```bash
docker compose up -d --build
```

- Фронтенд: http://localhost:3000
- API + Swagger: http://localhost:8000/docs

При старте бэкенд дожидается PostgreSQL, создаёт таблицы и наполняет базу тестовыми данными (`initdb.py`). База хранится в volume и переживает перезапуск; сбросить — `docker compose down -v`.

Остановить:

```bash
docker compose down
```

## Переменные окружения

| Переменная            | Сервис   | Назначение                                   |
|-----------------------|----------|----------------------------------------------|
| `SECRET_KEY`          | backend  | Ключ подписи JWT                             |
| `DATABASE_URL`        | backend  | Строка подключения к PostgreSQL              |
| `PUBLIC_API_URL`      | backend  | Адрес бэкенда для ссылок на скачивание       |
| `CORS_ORIGINS`        | backend  | Разрешённые источники CORS (через запятую)   |
| `NEXT_PUBLIC_API_URL` | frontend | Адрес API для браузера (вшивается в сборку)  |

Создаются автоматически при инициализации базы:

| Логин      | Пароль                     | Роль     |
|------------|----------------------------|----------|
| `guest`    | `guest`                    | guest    |

## Уязвимость и эксплуатация

Эндпоинт `GET /search` ищет подстроку по содержимому **всех** документов и возвращает совпадения **без проверки прав доступа к папке**. Обычный пользователь (`guest`) не видит секретную папку `Admins` в интерфейсе, но через поиск может посимвольно, как через оракул, восстановить содержимое лежащих там документов.

`POC.py` автоматизирует атаку: перебирает символы, оставляя только те префиксы, что встречаются в целевом файле, и так реконструирует его содержимое.

Запуск против локального стенда:

```bash
python3 POC.py
```

Перед запуском проверьте в `POC.py`:
- `BASE_URL` — адрес эндпоинта `/search` (по умолчанию `http://127.0.0.1:8000/search`);
- `Authorization` — валидный JWT обычного пользователя (можно получить через `POST /token` или взять из запроса в DevTools, заголовок `Authorization: Bearer ...`);
- `TARGET_FILE` — имя целевого документа.

> Примечание: PoC использует стандартный `urllib`. Это сделано специально — клиент `httpx` через проброс-порт Colima (ssh-туннель) возвращает 502; `urllib` и `curl` работают стабильно.

## Примечания по безопасности

Значения в репозитории (`SECRET_KEY`, пароли в `initdb.py`, токен в `POC.py`, документы в `fastapi/static/documents/`) — часть учебного таска, а не настоящие секреты. Для реального развёртывания задайте собственный `SECRET_KEY` и пароль БД через `.env`.
